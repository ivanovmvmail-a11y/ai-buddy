# AI-buddy

ИИ-помощник для стажёров Авито: помогает быстрее освоиться в команде и приступить к работе.
Хакатон, трек Web/AI.

**Главная идея: план, который растёт вместе со стажёром, а решает человек.** И бот, который запоминает: наставник отвечает на вопрос один раз — следующий стажёр получает ответ сразу.

**Видео-демонстрация:** _ссылка появится здесь_

## Быстрый старт: запустить за 15 минут (Windows, пошагово)

Не нужно ничего знать о программировании — достаточно повторять шаги по порядку. Для Mac и Linux всё то же самое,
только вместо PowerShell — «Терминал».

**Что нужно:** компьютер с Windows 10/11, 8 ГБ памяти, 10 ГБ свободного места на диске и интернет.

**Шаг 1. Установить Docker Desktop** (один раз).
1. Скачайте установщик: [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/) → «Download for Windows».
2. Запустите его и соглашайтесь со всем по умолчанию. Если установщик попросит включить WSL 2 или перезагрузить
   компьютер — согласитесь и перезагрузите.
3. Откройте Docker Desktop (значок кита на рабочем столе или в меню «Пуск»). Подождите, пока внизу слева появится зелёная
   надпись **Engine running** — это может занять 1–2 минуты. Регистрироваться в Docker не обязательно: окно входа можно пропустить.

> Docker Desktop должен быть **открыт** всё время, пока работает проект.

**Шаг 2. Скачать проект.**
1. Откройте страницу проекта: [github.com/ivanovmvmail-a11y/ai-buddy](https://github.com/ivanovmvmail-a11y/ai-buddy).
2. Зелёная кнопка **Code** → **Download ZIP**.
3. Откройте скачанный архив и перетащите папку `ai-buddy-main` на рабочий стол (или: правой кнопкой по архиву →
   «Извлечь все…»).

(Если у вас установлен Git, вместо этого можно выполнить `git clone https://github.com/ivanovmvmail-a11y/ai-buddy.git`.)

**Шаг 3. Открыть терминал в папке проекта.**
Откройте папку `ai-buddy-main` (внутри видны папки `backend`, `frontend`, `docs` и файл `docker-compose.yml`; если
внутри только ещё одна папка `ai-buddy-main` — откройте её). Щёлкните
по адресной строке вверху окна проводника, сотрите адрес, напечатайте `powershell` и нажмите Enter. Откроется синее
или чёрное окно — это терминал, он уже «стоит» в папке проекта.

**Шаг 4. Запустить.** Скопируйте в терминал команду и нажмите Enter:

```bash
docker compose up --build
```

Первый запуск занимает **5–10 минут**: Docker скачивает и собирает всё нужное, по экрану бежит много текста — это
нормально, ничего не сломалось. Готово, когда текст перестал бежать, а среди последних строк есть `Ready` или
`healthy`. **Окно терминала не закрывайте** — если его закрыть, проект остановится.

**Шаг 5. Открыть сайт:** [http://localhost:3000](http://localhost:3000). Внизу слева — демо-панель: в списке «Войти
как» выберите пользователя. Дальше — [«Маршрут проверки»](#маршрут-проверки-17-минут-без-ключа) ниже.

Без ключа нейросети проект работает в «сценарном режиме»: весь маршрут проверки проходится, внизу слева написано
«сценарный режим (без ключа модели)». Как подключить нейросеть GigaChat — раздел [«Подключение GigaChat»](#подключение-gigachat).

**Остановить:** в окне терминала нажмите `Ctrl + C`. **Запустить снова:** та же команда `docker compose up --build`
(второй раз — за 1–2 минуты). **Начать с чистого листа** (стереть демо-данные):

```bash
docker compose down -v
```

### Если что-то пошло не так

| Что видно | Что сделать |
|---|---|
| `docker` не является именем командлета / `command not found` | Docker Desktop не установлен или терминал открыт до установки. Установите (шаг 1), закройте терминал и откройте заново (шаг 3) |
| `Cannot connect to the Docker daemon`, `error during connect`, `pipe ... dockerDesktopLinuxEngine` | Docker Desktop не запущен. Откройте его и дождитесь **Engine running**, затем повторите команду |
| `no configuration file provided: not found` | Терминал открыт не в папке проекта. В папке должен лежать `docker-compose.yml` — повторите шаг 3 |
| `port is already allocated` / `address already in use` | Порт 3000, 8000 или 3002 занят другой программой. Закройте её (или перезагрузите компьютер) и повторите команду |
| `no space left on device` | Мало места на диске. Освободите 10 ГБ; в Docker Desktop: Settings → Resources → можно увеличить диск |
| Сайт не открывается, хотя всё запустилось | Подождите ещё минуту и обновите страницу (F5). Проверьте, что адрес ровно `http://localhost:3000` |
| «Примените новые миграции» | Осталась база от старой версии. Выполните `docker compose down -v`, затем `docker compose up --build` |
| После ключа GigaChat внизу слева всё ещё «сценарный режим» | Файл ключей называется не `.env` (Блокнот мог сохранить `.env.txt`) или проект не перезапущен — см. «Подключение GigaChat» |

## Зачем: цифры организаторов (12.11) и что меняем
| Сейчас у стажёров Авито | Что делает AI-buddy | Что замеряем в пилоте |
|---|---|---|

| Наставник тратит **~5 ч в неделю** первые 2–3 месяца: доступы, задачи, погружение, 1:1 | Доступ и отгул — черновиком за 2 клика; ответы по документам с источником; рост уровня — кнопкой «Поднять уровень» вместо разговора | Часы наставника в неделю |
| Частые вопросы: организационные (доступы, оборудование, документы), по задачам, по инструментам, развитие | Отвечает по документам команды, оргвопросы — сразу к HR BP, «нет в документах» — честно и с черновиком вопроса | Доля вопросов, закрытых без человека (панель Grafana) |
| До первой самостоятельной задачи ~2 недели, адаптация ~2 месяца | План недель 1–2 со сроками и напоминаниями | Дни до закрытия недели 1–2 |

две группы одного потока стажёров (с ботом и без), замер в конце недели 2 и месяца 2 ([SPEC, раздел 10](docs/SPEC.md)).

**Правила работы для людей и ИИ — в [AGENTS.md](AGENTS.md).** Доска задач — [.ai/STATUS.md](.ai/STATUS.md).

## Запуск через Docker (основной способ)

Нужен только [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
docker compose up --build
```

- сайт — http://localhost:3000
- backend — http://localhost:8000/health
- Grafana — http://localhost:3002, [готовая панель и настройки входа](ops/grafana/README.md)
- Redis — внутри Docker, хранит feature flags, переключённые на ходу (порт наружу не открыт)
- Apache Kafka — внутри Docker, принимает события продукта (порт наружу не открыт); первый запуск из-за неё скачивает на ~400 МБ больше
- база PostgreSQL + pgvector — внутри Docker (порт наружу не открыт, чтобы не мешать установленному у вас PostgreSQL); консоль: `docker compose exec db psql -U buddy -d ai_buddy` (тестовые учётные данные `buddy` / `buddy`)

**Без ключей** всё запускается в **сценарном режиме** (`LLM_PROVIDER=scenario`, спека [003](docs/specs/003-scenario-mode/spec.md)): весь маршрут демо проходится — следующий шаг по плану, черновик заявки на доступ с подтверждением, отказ на чужие данные, ответ по документам с источником, «в базе нет» с черновиком вопроса наставнику. Ответы собираются из данных сервисов и документов, без нейросети; в интерфейсе это подписано.
Чтобы подключить нейросеть: `cp backend/.env.example backend/.env`, указать `LLM_PROVIDER` и ключ (см. «Подключение GigaChat»), перезапустить `docker compose up --build`.

Остановить: `docker compose down`. Стереть базу и начать с нуля: `docker compose down -v`.

## Запуск для разработки (без Docker)

Нужны: [Git](https://git-scm.com), [Node.js LTS](https://nodejs.org), [uv](https://docs.astral.sh/uv/).

```bash
# 1. Backend (http://localhost:8000/health)
cd backend
cp .env.example .env        # и заполнить ключи
uv sync
uv run flask --app app.main run --debug --port 8000

# 2. Frontend (http://localhost:3000) — в другом терминале
cd frontend
cp .env.example .env.local
npm install
npm run dev
```

Без ключей backend работает в сценарном режиме `LLM_PROVIDER=scenario`. Для разработки есть `LLM_PROVIDER=echo` — просто повторяет сообщение.

## Подключение GigaChat
**Провайдер:** GigaChat (Сбер). **Модель:** `GigaChat-2` (рекомендуем, см. таблицу ниже). Документация провайдера: [developers.sber.ru/docs/ru/gigachat](https://developers.sber.ru/docs/ru/gigachat/api/overview).

1. [developers.sber.ru/studio](https://developers.sber.ru/studio) → создать проект GigaChat API → скопировать **Authorization Key**.
2. Создать файл настроек: `cp backend/.env.example backend/.env`.
3. В `backend/.env` заполнить переменные:

   | Переменная | Значение |
   |---|---|
   | `LLM_PROVIDER` | `gigachat` |
   | `GIGACHAT_CREDENTIALS` | Authorization Key из шага 1 |
   | `GIGACHAT_SCOPE` | версия API ключа: `GIGACHAT_API_PERS` — физлицо (по умолчанию), `GIGACHAT_API_B2B` — ИП/юрлицо, пакеты токенов, `GIGACHAT_API_CORP` — ИП/юрлицо, оплата по факту. **Должна совпадать с ключом**, иначе GigaChat отказывает в доступе |
   | `GIGACHAT_MODEL` | `GigaChat-2` (по умолчанию; `GigaChat-2-Max` — тоже работает) |

4. Перезапустить: `docker compose up --build` (без Docker — перезапустить backend, см. «Запуск для разработки»).
5. Проверить: http://localhost:8000/health показывает `"llm_provider": "gigachat"`, а внизу слева, в демо-панели, нет надписи «сценарный режим (без ключа модели)» — значит, отвечает модель.

**Как создать `backend/.env` на Windows без команд.** В папке проекта откройте `backend`, скопируйте файл `.env.example`
и вставьте его сюда же (Ctrl+C, Ctrl+V) — получится `.env - копия.example`. Переименуйте его ровно в `.env` (Windows
спросит, точно ли менять расширение, — «Да»). Откройте его Блокнотом (правой кнопкой → «Открыть с помощью» →
«Блокнот»), впишите значения из таблицы выше и сохраните (Ctrl+S). **Не используйте «Сохранить как…» в Блокноте** — он
допишет `.txt`, и получится `.env.txt`, которого проект не увидит. Проверить: в проводнике «Вид» → «Расширения имён
файлов» — файл должен называться `.env`, без `.txt`. Затем в терминале остановите проект (Ctrl+C) и снова
выполните `docker compose up --build`.

Сертификат Минцифры уже лежит в репозитории (`backend/certs/russian_trusted_root_ca.cer`, источник — [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt)) и подключается автоматически. Ничего делать не нужно.

**Какую модель выбрать (провайдер для проверки — GigaChat).**

| Модель (`GIGACHAT_MODEL`) | Золотой набор | Страховка сервера заменила ответ | Время ответа |
|---|---|---|---|
| **`GigaChat-2` — рекомендуем (по умолчанию)** | **132 из 132** (прогон 14.11 на итоговой версии, после полной проверки; весь набор вместе с «живыми» и разговорными формулировками; [отчёт](docs/golden-report-gigachat.md)). Три прогона подряд: 132, 132 и 131 — в одном модель ответила на «как поднять песочницу?» по соседнему документу; это разброс модели, от прогона к прогону такой вопрос может быть другим | 7 | ~0,4 с |
| `GigaChat-2-Max` | 50 из 55 (прогон 12.11 днём, только основные вопросы) | 4 | ~3,2 с |
| без ключа (`LLM_PROVIDER=scenario`) | 130 из 130: основные вопросы, «живые» формулировки из проверок 12–13.11 и разговорные сообщения ([отчёт](docs/golden-report.md)); 2 вопроса «другими словами» — только с моделью | не нужна | <0,1 с |

Max реже выдумывает (страховка понадобилась 4 раза) и лучше понимает вопросы, заданные не словами документа, но на нашем наборе слишком охотно готовит действия: на «что мне делать дальше?» сразу предлагает черновик заявки вместо ответа, а в одном ответе назвал напоминание «заявлением на отгул». Черновики без подтверждения человеком не выполняются, права проверяет сервер — но для проверки рекомендуем `GigaChat-2`. Если модель отвечает «в документах нет», хотя абзац нашёлся, или советует то, чего в документах нет, сервер заменяет такой ответ на абзац с источником или на честное «в документах нет — спроси наставника» (`backend/app/llm/scenario_provider.py`, `docs_guard`). Противоречия в документах и правило отгула сервер тоже показывает сам, не полагаясь на модель. Так же — правила продукта, которые не должны зависеть от модели: чужой уровень и чужой план, «одобри мою заявку» от стажёра, админ-права, причина отгула, нерабочие вопросы (`policy_reply`); на «что у Ани зависло?» наставник получает точную сводку из плана; во фразе с двумя просьбами модель выполняет первую, а про вторую сервер говорит честно. Подойдёт и любая OpenAI-совместимая модель (`LLM_PROVIDER=openai`, `OPENAI_BASE_URL`, `OPENAI_MODEL`), но на нашем наборе мы её не проверяли.

## Интеграции: как устроено и что заменяется при внедрении

Корпоративные сервисы Авито из ТЗ (чек-лист новичка, доступы, найм, ИИ-крон, события) — **синтетические имитации** в
`backend/app/mcp_server/`. Они оформлены как **MCP-сервер** на официальном SDK (20 инструментов, сеть Streamable HTTP или stdio, права
проверяет сам сервер) и проверены тестами протокола. Запустить его отдельно и подключить к любому MCP-клиенту:

```bash
cd backend && uv run --extra mcp python -m app.mcp_server.server --user intern-anya
```

Подробно, с примером для Claude Desktop, — [backend/app/mcp_server/README.md](backend/app/mcp_server/README.md).

**Агент ходит к сервисам по MCP через сеть.** В Docker MCP-сервер — **отдельная служба `mcp`** (`app/mcp_server/http_server.py`, Streamable HTTP, порт наружу не открыт), а агент чата вызывает её **MCP-клиентом** официального SDK (`AGENT_SERVICES=mcp`, `MCP_URL=http://mcp:8001/mcp`, шлюз `backend/app/agent/services.py`): на каждый вызов — сессия к MCP-серверу от имени вошедшего пользователя (заголовок `X-AI-Buddy-User` ставит backend по входу, не модель; без ключа службы `MCP_SERVICE_TOKEN` сервер отвечает 401), `tools/call`, ответ — `structuredContent`; права проверяет сам MCP-сервер, отказ приходит ошибкой протокола. Права проверяются и до вызова (`app/agent/tools.py`). Весь набор тестов backend проходит в обоих режимах (`AGENT_SERVICES=mcp uv run --extra mcp pytest`).

Увидеть вызовы: `docker compose logs mcp` — строки `mcp http user=…` на каждый вызов инструмента из чата.

**Честно о прототипе:** MCP-сервер один на все корпоративные сервисы (в Авито — свой сервер у каждого сервиса за MCP Hub), пользователь передаётся заголовком от доверенного backend (в Авито — токен SSO). Без Docker и в облачной версии MCP-сервер работает в памяти процесса backend (`MCP_URL` пуст) — протокол тот же. Два действия намеренно не идут через MCP: подтверждение отгула и напоминание по просьбе выполняет доверенный вызов после кнопки «Подтвердить» человека — инструмента «подтвердить» у MCP-сервера нет, модель не может подтвердить сама. Экраны плана и заявок (HTTP API) читают сервисы напрямую.

| Сейчас (прототип) | При внедрении |
|---|---|
| Вход заголовком `X-User-Id` (`app/agent/users.py`) | SSO и ролевая модель Авито |
| Имитации сервисов в `app/mcp_server/` — одна служба MCP по Streamable HTTP с ключом службы | Настоящие MCP-серверы сервисов Авито (MCP Hub), меняется `MCP_URL`; пользователь — из SSO |
| GigaChat / сценарный режим (`LLM_PROVIDER`) | A-Vibe или другая модель — одна переменная |
| Кнопка «Следующий день» | ИИ-крон по расписанию |
| Таблица событий → Grafana; те же события — в Apache Kafka (служба `kafka`, топик `ai-buddy.events`) | Clickstream поверх Kafka Авито: меняется адрес брокера |
| Feature flags в Redis (`GET` / `POST /features`, `FEATURE_FLAGS`) | Система feature flags Авито |

**Feature flags работают на деле** ([спека 006](docs/specs/006-feature-flags/spec.md)): четыре функции включаются и выключаются без правки кода — при запуске (`FEATURE_FLAGS="quick_access=off"`) и на ходу, без перезапуска; значение на ходу лежит в **Redis** (в Docker — служба `redis`; Redis недоступен — backend работает по значениям запуска). Проверить: откройте http://localhost:8000/docs → `POST /features` или выполните

```bash
curl -X POST http://localhost:8000/features -H "X-User-Id: mentor-petr" -H "Content-Type: application/json" -d "{\"name\":\"quick_access\",\"enabled\":false}"
```

После этого «Сделать за меня» у «Запросить базовые доступы» готовит черновик с «Подтвердить» вместо выдачи в один клик. «Сброс» в демо-панели возвращает флаги к начальным.

**События уходят в Apache Kafka** ([спека 304](docs/specs/304-event-stream/spec.md)): каждое событие продукта (вопрос задан, заявка создана, пункт закрыт, задание сдано) после записи в таблицу дублируется в топик `ai-buddy.events` — так его в Авито забрал бы Clickstream. Текстов вопросов и ответов в событиях нет. Kafka не может помешать работе: отправка идёт в фоне, от службы `kafka` никто не зависит. Посмотреть события (сначала сделайте пару действий на сайте):

```bash
docker compose exec kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic ai-buddy.events --from-beginning --timeout-ms 5000
```

Счётчики отправки — http://localhost:8000/docs → `GET /events/stream`.

**Полная карта «что заменить → в каком файле» и входы для систем Авито — [docs/INTEGRATION.md](docs/INTEGRATION.md).** Коротко:
- **API описан в OpenAPI 3.1**: http://localhost:8000/docs (Swagger UI) и `/openapi.json`. Описание собирается из кода и не расходится с ним.
- **Система найма → `POST /integrations/hired`**: итоги собеседования (карта навыков), и бот сам пересобирает персональный план стажёра.
- **Mattermost → `POST /integrations/mattermost`**: slash-команда `/buddy` или исходящий вебхук. Отвечает тот же агент, с теми же правами и черновиками.
- В Docker оба входа включены с демо-ключом `local-docker-demo`. Пример запроса — в docs/INTEGRATION.md.

## Маршрут проверки (17 минут, без ключа)

> **Совет эксперту.** Маршрут ниже проходится и без ключа ИИ: сценарный режим собирает ответы из данных сервисов и документов
> по ключевым словам. Свои вопросы «как живой стажёр» лучше задавать **с ключом** (раздел «Подключение GigaChat»): модель
> понимает формулировки шире. Действия, права, отгул, данные плана и оргвопросы работают одинаково в обоих режимах — их
> обрабатывает сервер, а не модель.

Запустите `docker compose up --build` и откройте http://localhost:3000. Слева — колонка навигации: карточка пользователя, разделы (**«Главная»**, **«Мой план»**, **«Мой профиль»**) и внизу **демо-панель**: список **«Войти как»**, кнопки **«Следующий день»** и **«Сброс»** (возвращает демо-данные к началу — нажмите перед проверкой). Справа — чат с вкладками «Помощник / Учёба / Заявки». В шапке — переключатель светлой/тёмной темы и колокольчик 🔔. На телефоне колонка открывается кнопкой ☰, чат — вкладкой «Чат».

**Демо-время.** В демо свой календарь: после «Сброс» сегодня — среда 11.11.2026, дата видна в демо-панели («Сегодня в демо: ср, 11.11»), даты отгула и напоминаний считаются от неё. В карточке стажёра — его день и дата выхода («День 2 · с 10.11»). День меняется **только** кнопкой «Следующий день», сразу у всех стажёров. Если сайт не открывается — проверьте, что порты **3000, 8000, 3002** свободны (не запущены другие серверы разработки), и перезапустите `docker compose up`.

Если проект уже запускался раньше из старой версии репозитория и появляется «примените новые миграции» — база в Docker создана до новых таблиц (SQL-миграции применяются только при первом создании базы). Пересоздайте её: `docker compose down -v`, затем `docker compose up --build` (демо-данные загрузятся заново).
