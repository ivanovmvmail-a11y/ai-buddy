# AI-buddy

ИИ-помощник для стажёров Авито: помогает быстрее освоиться в команде и приступить к работе.
Хакатон, трек Web/AI.

**Правила работы для людей и ИИ — в [AGENTS.md](AGENTS.md).** Доска задач — [.ai/STATUS.md](.ai/STATUS.md).

## Запуск через Docker (основной способ)

Нужен только [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
docker compose up --build
```

- сайт — http://localhost:3000
- backend — http://localhost:8000/health
- Grafana — http://localhost:3002, [готовая панель и настройки входа](ops/grafana/README.md)
- база PostgreSQL + pgvector — внутри Docker (порт наружу не открыт, чтобы не мешать установленному у вас PostgreSQL); консоль: `docker compose exec db psql -U buddy -d ai_buddy` (тестовые учётные данные `buddy` / `buddy`)

**Без ключей** всё запускается в **сценарном режиме** (`LLM_PROVIDER=scenario`, спека [003](docs/specs/003-scenario-mode/spec.md)): весь маршрут демо проходится — следующий шаг по плану, черновик заявки на доступ с подтверждением, отказ на чужие данные, ответ по документам с источником, «в базе нет» с черновиком вопроса наставнику. Ответы собираются из данных сервисов и документов, без нейросети; в интерфейсе это подписано.
Чтобы подключить нейросеть: `cp backend/.env.example backend/.env`, указать `LLM_PROVIDER` и ключ (см. «Подключение GigaChat»), перезапустить `docker compose up --build`.

Остановить: `docker compose down`. Стереть базу и начать с нуля: `docker compose down -v`.

## Запуск для разработки (без Docker)

Нужны: [Git](https://git-scm.com), [Node.js LTS](https://nodejs.org), [uv](https://docs.astral.sh/uv/).

```bash
# 1. Backend (http://localhost:8000/health)
cd backend
cp .env.example .env        # и заполнить ключи
uv sync
uv run flask --app app.main run --debug --port 8000

# 2. Frontend (http://localhost:3000) — в другом терминале
cd frontend
cp .env.example .env.local
npm install
npm run dev
```

Без ключей backend работает в сценарном режиме `LLM_PROVIDER=scenario`. Для разработки есть `LLM_PROVIDER=echo` — просто повторяет сообщение.

## Подключение GigaChat
**Провайдер:** GigaChat (Сбер). **Модель:** `GigaChat-2` (рекомендуем, см. таблицу ниже). Документация провайдера: [developers.sber.ru/docs/ru/gigachat](https://developers.sber.ru/docs/ru/gigachat/api/overview).

1. [developers.sber.ru/studio](https://developers.sber.ru/studio) → создать проект GigaChat API → скопировать **Authorization Key**.
2. Создать файл настроек: `cp backend/.env.example backend/.env`.
3. В `backend/.env` заполнить переменные:

   | Переменная | Значение |
   |---|---|
   | `LLM_PROVIDER` | `gigachat` |
   | `GIGACHAT_CREDENTIALS` | Authorization Key из шага 1 |
   | `GIGACHAT_SCOPE` | версия API ключа: `GIGACHAT_API_PERS` — физлицо (по умолчанию), `GIGACHAT_API_B2B` — ИП/юрлицо, пакеты токенов, `GIGACHAT_API_CORP` — ИП/юрлицо, оплата по факту. **Должна совпадать с ключом**, иначе GigaChat отказывает в доступе |
   | `GIGACHAT_MODEL` | `GigaChat-2` (по умолчанию; `GigaChat-2-Max` — тоже работает) |

4. Перезапустить: `docker compose up --build` (без Docker — перезапустить backend, см. «Запуск для разработки»).
5. Проверить: http://localhost:8000/health показывает `"llm_provider": "gigachat"`, а в шапке сайта нет надписи «сценарный режим (без ключа модели)» — значит, отвечает модель.

Сертификат Минцифры уже лежит в репозитории (`backend/certs/russian_trusted_root_ca.cer`, источник — [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt)) и подключается автоматически. Ничего делать не нужно.

**Какую модель выбрать (провайдер для проверки — GigaChat).**

| Модель (`GIGACHAT_MODEL`) | Золотой набор (55 вопросов) | Страховка сервера заменила ответ | Время ответа |
|---|---|---|---|
| **`GigaChat-2` — рекомендуем (по умолчанию)** | **55 из 55**, два прогона подряд ([отчёт](docs/golden-report-gigachat.md)) | 9–11 | ~0,7 с |
| `GigaChat-2-Max` | 50 из 55 | 4 | ~3,2 с |
| без ключа (`LLM_PROVIDER=scenario`) | 53 из 53 ([отчёт](docs/golden-report.md)); 2 вопроса «другими словами» — только с моделью | не нужна | <0,1 с |

Max реже выдумывает (страховка понадобилась 4 раза) и лучше понимает вопросы, заданные не словами документа, но на нашем наборе слишком охотно готовит действия: на «что мне делать дальше?» сразу предлагает черновик заявки вместо ответа, а в одном ответе назвал напоминание «заявлением на отгул». Черновики без подтверждения человеком не выполняются, права проверяет сервер — но для проверки рекомендуем `GigaChat-2`. Если модель отвечает «в документах нет», хотя абзац нашёлся, или советует то, чего в документах нет, сервер заменяет такой ответ на абзац с источником или на честное «в документах нет — спроси наставника» (`backend/app/llm/scenario_provider.py`, `docs_guard`). Противоречия в документах и правило отгула сервер тоже показывает сам, не полагаясь на модель. Подойдёт и любая OpenAI-совместимая модель (`LLM_PROVIDER=openai`, `OPENAI_BASE_URL`, `OPENAI_MODEL`), но на нашем наборе мы её не проверяли.

## Интеграции: как устроено и что заменяется при внедрении

Корпоративные сервисы Авито из ТЗ (чек-лист новичка, доступы, найм, ИИ-крон, события) — **синтетические имитации** в
`backend/app/mcp_server/`. Они оформлены как **MCP-сервер** на официальном SDK (8 инструментов, stdio, права проверяет
сам сервер) и проверены тестами протокола. Запустить его отдельно и подключить к любому MCP-клиенту:

```bash
cd backend && uv run --extra mcp python -m app.mcp_server.server --user intern-anya
```

Подробно, с примером для Claude Desktop, — [backend/app/mcp_server/README.md](backend/app/mcp_server/README.md).

**Честно о прототипе:** веб-агент вызывает те же функции сервисов **в одном процессе**, а не по сети через MCP. Так проект
запускается одной командой, а права проверяются на сервере перед каждым вызовом (`app/agent/tools.py`) и ещё раз внутри
сервиса. При внедрении меняется один слой — `app/agent/onboarding_tools.py` становится MCP-клиентом к настоящим
MCP-серверам Авито; агент, права, черновики и интерфейс не меняются.

| Сейчас (прототип) | При внедрении |
|---|---|
| Вход заголовком `X-User-Id` (`app/agent/users.py`) | SSO и ролевая модель Авито |
| Имитации сервисов в `app/mcp_server/` | Настоящие MCP-серверы сервисов Авито |
| GigaChat / сценарный режим (`LLM_PROVIDER`) | A-Vibe или другая модель — одна переменная |
| Кнопка «Следующий день» | ИИ-крон по расписанию |
| Таблица событий → Grafana | Clickstream / Kafka |

## Маршрут проверки (10–15 минут, без ключа)

Запустите `docker compose up --build` и откройте http://localhost:3000. Пользователь переключается списком **«Войти как»** в шапке, там же кнопки **«Следующий день»** (сдвигает демо-время) и **«Сброс»** (возвращает демо-данные к началу — нажмите перед проверкой). Без ключа ответы помечены «Сценарный ответ».

| # | Что сделать | Что должно произойти |
|---|---|---|
| 1 | «Войти как» → **Аня Смирнова — стажёр** | Слева план на 3 месяца (день 2, недели 1–2 подробно), справа чат. Бот пишет первым: какой сегодня день, сколько закрыто, следующий шаг |
| 2 | У пункта «Открыть пространство Платформы объявлений» (метка «здесь помогу подробно») нажать **«Объяснить»**, затем то же у «Разобрать документы Платформы объявлений» (метка «ты это знаешь») | Глубина объяснения зависит от уровня Ани в теме: первое — по шагам, второе — коротко. Практическое задание, источник, кнопки «Полезно / Не полезно» |
| 3 | У пункта «Запросить базовые доступы» **«Сделать за меня»** → **«Подтвердить»** | Карточка-черновик заявки (ресурс, права «чтение», кто согласует). До подтверждения ничего не создаётся. Учебный Jira выдаётся сразу — пункт «сделано» |
| 3а | У пункта «Открыть пространство Платформы объявлений» **«Сделать за меня»** → **«Подтвердить»** | Заявка `REQ-…` ушла наставнику Петру; пункт «ждёт другого человека», бот обещает напомнить |
| 4 | «Войти как» → **Пётр Волков — наставник** | Карточка Ани: что зависло, частые темы, уровень по темам, итоги недели. Блок «Ждут твоего одобрения» → **«Одобрить»**. В плане Ани у пункта «Назначить регулярные встречи 1:1» — **«Готово»** |
| 5 | Снова **Аня** | Пункт с доступом закрыт, следующий шаг сместился |
| 6 | «Войти как» → **Иван Кузнецов — стажёр** | Другая команда (Авито Доставка), другой план и другие метки уровня. У Ивана 8-й день — бот сразу присылает **итоги недели 1** (только факты). Вкладка **«Мой профиль»** — что бот о нём знает. Спросить «Кого я жду?» — ответ из его заявок. **«Следующий день»** → в колокольчике 🔔 напоминание о просроченном пункте |
| 7 | Снова **Аня**, в чате по очереди: «Покажи план Ивана» · «Какие статусы проходит учебное отправление в Доставке?» · «Где взять рабочий ноутбук?» | Отказ без подробностей · ответ без данных чужой команды · «в базе нет» и черновик вопроса наставнику |
| 8 | Grafana http://localhost:3002 → панель **«AI-buddy — польза вживую»** | Вопросы, темы, оценки «полезно». Отчёт золотого набора — [docs/golden-report.md](docs/golden-report.md). Модель меняется одной переменной `LLM_PROVIDER` |

Если сайт не открывается — проверьте, что порты **3000, 8000, 3002** свободны (не запущены другие серверы разработки), и перезапустите `docker compose up`.

## Проверка
Каждый PR автоматически проверяет GitHub Actions (`.github/workflows/ci.yml`): тесты и покрытие backend (отчёт — артефакт `coverage-backend`), линтер и сборка frontend, запуск всего проекта через `docker compose up`.

- `GET http://localhost:8000/health` → `{"status":"ok", ...}`
- Сценарий целиком — «Маршрут проверки» выше.
- Тесты backend: `cd backend && uv run --extra mcp pytest --cov=app --cov-report=term-missing`
- Тесты frontend с покрытием: `cd frontend && npm run test:cov` (порог — 80% строк)
- Золотой набор (48 контрольных вопросов, метрики качества): `cd backend && uv run python -m golden.run` — отчёты [сценарный режим](docs/golden-report.md), [GigaChat](docs/golden-report-gigachat.md) (прогон до расширения набора, 37 вопросов)

## Облако (бонус): всё на Railway
- **Сайт:** https://ai-buddy-site-production.up.railway.app
- **Backend:** https://ai-buddy-production-9970a770.up.railway.app (`/health`)
- **База:** Supabase (миграции уже применены), подключение через Session pooler.

Оба сервиса в одном проекте Railway, собираются из Docker-файлов и сами обновляются при мерже в `main`.
- `ai-buddy` (backend): Root Directory `/backend`, Healthcheck `/health`, домен на порт 8000. Variables: `PORT=8000`, `LLM_PROVIDER=gigachat`, `EMBEDDINGS_PROVIDER=fake`, `GIGACHAT_CREDENTIALS`, `DATABASE_URL` (Supabase → Connect → Direct → Session pooler), `FRONTEND_ORIGINS` = адрес сайта, `DEMO_KEY` = код-слово для кнопок «Сброс» / «Следующий день» (чтобы посетители не сбросили данные во время показа; знает только команда).
- `ai-buddy-site` (frontend): Root Directory `/frontend`, домен на порт 3000. Variables: `NEXT_PUBLIC_API_URL` = адрес backend, `PORT=3000`.

Почему не другие хостинги (проверено из России 11.11.2026): Render, `*.onrender.com` и `*.vercel.app` не открываются; Koyeb закрыл бесплатную регистрацию; Netlify отдаёт файлы больше ~14 КБ с зависанием, и сайт не загружается. Пробный период Railway — 30 дней / $5.
