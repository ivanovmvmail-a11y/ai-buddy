## 5. Найденные ошибки

**Блокеров нет:** проект запускается, основной сценарий проходится.

### Важно

- **В1. Маршрут проверки в README устарел.** В нём 8 шагов образца 10.11: нет отгула, сравнения планов, предложения поднять уровень, руководителя Ольги. Эксперт идёт именно по README. Вдобавок шаг 7 README («Какие статусы проходит учебное отправление в Доставке?» от Ани, ожидается «ответ без данных чужой команды») даёт абзац про `git push`.
- **В2. Бот выдаёт абзац не по теме с подписью «Нашёл в документе».** Воспроизведение: войти как Аня, спросить «а когда зп приходит?» → абзац про ревью. То же на «что такое CI и зачем он мне», «Покажи материалы для наставника». Причина — совпадение двух случайных слов считается ответом (`_from_docs` в `backend/app/llm/scenario_provider.py`).
- **В3. Вопрос о чужом уровне показывает свой.** Аня: «какой уровень по git у Кирилла?» → «По профилю: ci — новичок, git — знаком, sql — уверенно» (это её данные). Нужно: «это данные другого стажёра».
- **В4. Два действия в одной фразе — второе теряется молча.** «оформи доступ в джиру и напомни завтра» → только черновик заявки. Эксперты на вебинаре прямо говорили про действия; хотя бы честно сказать «напоминание сделаю отдельно».
- **В5. Метрика «закрыто без человека» завышена.** Ответы не по теме из В2 считаются «закрытыми с источником» (в Grafana 53,8%). Эксперт, сверивший цифру с чатом, перестанет верить всей панели.
- **В6. Шесть тестов падают на Windows.** `cd backend && uv run --extra mcp pytest` → `tests/mcp/test_protocol.py::test_invalid_startup_identity_exits_before_protocol` ×6: русский текст ошибки приходит в неверной кодировке. На Linux и в CI проходят. Эксперт на Windows увидит красное.
- **В7. Документы отстают от кода.** Нет SDD-спецификаций на персональный план, предложения по уровню, отгул и уведомления (в `docs/specs/` только функции до 11.11) — а ТЗ требует спецификации, «по которым велась разработка AI-функций». В README дважды написано «48 контрольных вопросов» при 55 в наборе. Ссылки на видео нет.

| 7 | Золотой набор, метрики, Grafana | выше средней | Работает вживую | У большинства — слайд с придуманными цифрами |

**Главное УТП — одно: связка 1 + 2 как единая история «план, который растёт вместе со стажёром, а решает человек».** Эксперт сам одобрил персонализацию и попросил показать наглядно. Это прямо отвечает на обе цели кейса: стажёр не тратит время на то, что уже умеет, наставник тратит 10 секунд на кнопку вместо получасовой встречи. И у вас есть готовая сцена на 40 секунд: Аня жмёт «Это я уже знаю» → у Петра появляется предложение → он жмёт «Поднять уровень» → у Ани на глазах исчезает пункт и приходит уведомление. Этого нет ни у кого с «чатом по чек-листу».

**Звучит как «у всех так»:** отгул (он в тексте кейса), черновик с подтверждением, «работает без ключа», «MCP-сервер», «не выдумывает». Это всё нужно, но в первые 30 секунд этим не открывают.

**Чего не хватает до «вот это да»:**
1. **Чтобы свободный чат не подводил.** Сейчас первая же «живая» фраза эксперта может получить ответ не по теме — и впечатление от сильной механики пропадает.
2. **Наглядности главной идеи.** Сравнение планов должно читаться за три секунды: слева Аня, справа Кирилл, общие пункты серые, разные — цветом.
3. **Практики с результатом.** Эксперт на вебинаре приводил пример: не «получи доступ к Grafana», а «открой, найди два дашборда, посчитай время ответа». У вас «задание на практике» — одна строчка без проверки.
4. **Цифры «было → стало».** В материалах тренинга прямо сказано: покажите путь до и после. Например: «заявка на доступ — было 5 шагов и поиск ответственного, стало 2 клика».
