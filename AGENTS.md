# AGENTS.md — правила для всех ИИ-агентов и людей в проекте

Проект: **AI-buddy** — ИИ-помощник для стажёров Авито (хакатон, трек Web/AI).
Спецификация: `docs/SPEC.md`. Контракт API: `docs/API.md`. Решения: `docs/DECISIONS.md`.

## Кто есть кто
| Агент | Чей | Зона ответственности (папки) |
|---|---|---|
| **Claude Code** | Виктор | `frontend/`, `backend/app/agent/` (промпты, логика агента), `backend/app/llm/`, `docs/API.md`, `docs/SPEC.md` |
| **Codex** | тиммейт | `backend/app/rag/` (RAG, эмбеддинги, поиск), `backend/app/mcp_server/` (MCP-сервер, моки корпоративных сервисов), `backend/app/db/` и `supabase/migrations/` (схема БД, миграции) |
| Люди | команда | ревьюят и мержат PR, принимают продуктовые решения |

Если задача требует правки в чужой зоне — **не правь молча**: опиши, что нужно, в `.ai/HANDOFF.md`.

## Обязательный цикл работы (для каждого агента, каждой задачи)
1. **Перед началом:** `git checkout main && git pull`. Прочитай `.ai/STATUS.md`, свой журнал и журнал другого агента (`.ai/claude-log.md`, `.ai/codex-log.md`), `.ai/HANDOFF.md`.
2. **Ветка:** одна задача = одна ветка: `claude/<коротко-о-задаче>` или `codex/<коротко-о-задаче>`. **Никогда не коммить и не пушь в `main` напрямую.** Никогда `git push --force`.
3. **Отметься** в `.ai/STATUS.md`: строка с задачей, статус `в работе`.
4. **Работай** только в своей зоне. Маленькие коммиты с понятными сообщениями на русском или английском.
5. **Проверь** перед PR: код запускается, `/health` отвечает, ничего не сломано (см. README → «Проверка»).
6. **Обнови** свой журнал `.ai/<агент>-log.md` (что сделано, что дальше, вопросы) и строку в `STATUS.md` → `на ревью`.
7. **Открой PR** в `main` по шаблону. Мержит **только человек** после ревью.

## Жёсткие правила
- **Секреты только в `.env`** (он в `.gitignore`). В коде, логах, PR и чатах — никогда. Новые переменные добавляй в `.env.example` с пустым значением.
- Репозиторий **публичный** — всё, что закоммичено, видят все.
- Изменения в `docs/API.md` (контракт фронт↔бэк) — отдельным PR с пометкой `[API]`, чтобы другой агент увидел.
- Новая зависимость, смена библиотеки или архитектуры → строка в `docs/DECISIONS.md`.
- Не удаляй и не переписывай чужие файлы журналов.
- Не трогай `.github/`, `AGENTS.md`, `CLAUDE.md` без просьбы человека.
- Если что-то непонятно в ТЗ — не выдумывай, запиши вопрос в свой журнал и спроси человека.

## Особенности Codex (работает в облаке на chatgpt.com/codex)
- Ключей и интернета у Codex нет. Код должен работать и тестироваться без них: `LLM_PROVIDER=echo`, внешние вызовы (GigaChat, Supabase) закрыты интерфейсом, в тестах используются заглушки.
- Изменения схемы БД — только SQL-файлами `supabase/migrations/<YYYYMMDDHHMMSS>_<описание>.sql`. К реальной базе их применяет Claude (через Supabase MCP) после мержа.
- Журнал (`.ai/codex-log.md`) и строка в `.ai/STATUS.md` обновляются **в том же PR**, что и код.
- Ветка Codex должна начинаться с `codex/`.

## Стек
- Backend: Python 3.12, FastAPI, uv (`backend/`).
- Frontend: Next.js (App Router) + TypeScript + Tailwind (`frontend/`).
- БД: Supabase (PostgreSQL + pgvector).
- LLM: GigaChat по умолчанию, провайдер переключается через `LLM_PROVIDER` в `.env` (см. `backend/app/llm/`).
- Деплой: frontend → Vercel, backend → Render. Автодеплой при мерже в `main`.

## Команды
```bash
# backend
cd backend && uv sync && uv run fastapi dev app/main.py   # http://localhost:8000/health
# frontend
cd frontend && npm install && npm run dev                 # http://localhost:3000
```
