# Общий PostgreSQL-пул

app.db.pool.PostgresPoolOwner — общая часть PostgresDocumentStore (RAG) и PostgresStore (онбординг).
Конструкторы не создают пул и не подключаются. Первое async-обращение на общем app.async_runner
получает один AsyncConnectionPool на **точное значение DATABASE_URL**: min_size=1, max_size=8,
ожидание соединения до 5 секунд, connect_timeout=5, dict_row. Это общий бюджет двух подсистем
в одном Python-процессе. Отдельные процессы имеют собственный бюджет.

Разные DSN/credentials не объединяются: читатель и владелец БД не должны разделять соединение.
Эквивалентные строки подключения с разным текстом также считаются разными ключами. Все вызовы
Flask/CLI/MCP проходят через app.async_runner; пул, открытие и закрытие остаются на одном loop.

Каждый адаптер владеет одной долей пула, независимо от числа запросов. Собственная блокировка
не даёт параллельным первым обращениям зарегистрировать адаптер дважды; общий менеджер
сериализует создание/последнее закрытие. close() адаптера идемпотентен и освобождает только его
долю. Физический пул закрывается после последнего владельца; следующий запрос может создать новый.
Нельзя закрывать адаптер, пока его собственные операции ещё выполняются. Закрытие пула соседней
подсистемы вручную через приватный _pool не поддерживается; использовать только store.close().

Это сохраняет работающий RAG при переходе онбординга в память после ошибки схемы. Завершение
RAG CLI (отдельный PR) освобождает его адаптер; если он последний владелец процесса, workers
закрываются полностью. При ошибке/отмене открытия незарегистрированный пул закрывается до повторной попытки.

SQL/ACL не меняются. RAG использует SET LOCAL search_path/app.rag_team внутри транзакции,
онбординг — свой REPEATABLE READ/advisory-lock. Commit/rollback перед возвратом соединения
исключает перенос команды/изоляции между запросами. Пользователи по-прежнему проверяются сервисами.

Тесты: tests/test_db_pool.py (гонки, владение, разные DSN, ошибки/отмена открытия) и
 tests/mcp/test_shared_pool.py (реальные запросы обеих подсистем, изоляция транзакционных настроек,
параллельная нагрузка ≤8 соединений, закрытие в обоих порядках, запасной режим онбординга).
Запуск из backend:

```bash
LLM_PROVIDER=echo uv run --extra mcp --frozen --offline pytest --mcp-postgres --rag-postgres --cov=app --cov-branch
```

PostgreSQL-тесты используют только свои временные контейнеры с уже скачанным pgvector/pgvector:pg17.
Новых переменных или зависимостей нет. Миграция для общего пула не требуется.
