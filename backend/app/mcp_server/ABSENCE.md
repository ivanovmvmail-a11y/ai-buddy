# Имитация отгула на один день

Демо-данные, не регламент Авито. Этот сервис не оформляет больничные, отпуск или
кадровые обращения. Причины: `personal` (личные дела), `family` (семейные дела),
`study` (учебные дела). Свободного текста причины и медицинских полей нет.

`absence.draft_absence(user_id, day, reason)` сохраняет черновик стажёра.
Доверенный UI показывает дату/причину/руководителя; после клика вызывает
`confirm_absence(user_id, draft_id)`. Входящие получает руководитель из профиля
стажёра, совпадающий с его командой. Он готовит `draft_decision(..., approve)` и
отдельно подтверждает через `confirm_decision`. Повтор подтверждения идемпотентен.
День не должен быть раньше текущей виртуальной даты стажёра; проверка повторяется
при подтверждении. На один день допускается одна pending/approved-заявка;
после отклонения можно создать новую. Отмена черновика — `drafts.cancel_draft`.

Только стажёр и назначенный руководитель читают полную заявку через
`get_request`/`list_requests`. Наставнику `list_absence_facts(user_id, intern_id)`
возвращает исключительно `{intern_id, day}` согласованных отсутствий своего
стажёра. Он не получает ни причину, ни id заявки, ни pending/rejected-историю.
HR/куратор и чужие пользователи получают тот же NotFound, что для отсутствующих
объектов. Payload событий содержит только status.

MCP: `absence_draft_request`, `absence_draft_decision`, `absence_get_request`,
`absence_list_requests`, `absence_list_facts`, `absence_get_draft`. Пользователь
привязан к запуску сервера. **Подтверждения не экспортированы в MCP**: модель
не может сама отправить/одобрить подготовленную заявку.

Миграции: shared `20261111120000_service_drafts.sql`, затем
`20261111120200_absence.sql` после базового onboarding. RLS и revoke включают
PUBLIC, существующие anon/authenticated и identity sequences.
Seed двух команд — `seed/absence.json`, хранение — InMemory или PostgreSQL
через общий OnboardingStore. Полный контракт интеграции — `.ai/HANDOFF.md`.

## Уведомления и сроки (чекпоинт 1)
Примените также `20261111161000_reminder_kinds.sql`. Подтверждение заявки уведомляет
руководителя (`absence_new`); через два виртуальных дня ожидания стажёр получает
`absence_pending`. Решение завершает оба ожидания и создаёт `absence_decided` автору.
При согласовании наставник получает только `absence_fact`: дату, без причины и ссылки на заявку.
В согласованный день появляется `absence_today`; сроки незакрытых пунктов сдвигаются на +1
ровно один раз. Cron и advance_day используют виртуальный день стажёра, Event.ts — реальные часы.
Сохранённые напоминания обеспечивают дедупликацию и после перезапуска.
