# Личная самопроверка

Демо-данные, не регламент Авито. В `seed/self_check.json` — по два вопроса с
вариантами на Git, SQL и CI для каждой из двух демо-команд. Вопросы ссылаются на
существующие синтетические RAG-документы; краткие пояснения Git/CI/SQL добавлены
в эти документы. Ссылки ведут на исходные markdown-файлы публичного репозитория.

`self_check.get_questions(user_id, topic)` возвращает только вопросы своей команды
без правильных вариантов и объяснений. `draft_answers(user_id, topic, answers)`
подготавливает ответы (`{question_id: индекс_с_нуля}`) на все вопросы темы.
UI показывает черновик, затем после клика вызывает
`confirm_answers(user_id, draft_id)`. В MCP подтверждения нет. Черновик содержит
версию набора, поэтому изменение банка между подготовкой и подтверждением
требует нового черновика. Повтор подтверждения идемпотентен.

Результат содержит разбор каждого вопроса: выбранный и правильный индекс,
объяснение, source_id и source_url. Суммарного балла/рейтинга нет. `get_result`
и `list_results` доступны только самому стажёру; наставник, руководитель, HR,
куратор и чужой стажёр получают NotFound. В events сохраняется исключительно
`self_check_completed` с `{"topic":"git|sql|ci"}` без ответов/баллов.
**Профиль и уровни навыков не меняются**; это полномочие наставника.

MCP: `self_check_questions`, `self_check_draft_answers`, `self_check_get_result`,
`self_check_list_results`, `self_check_get_draft`. Личность фиксируется запуском
процесса. Сервис использует InMemory/Postgres через общий OnboardingStore;
reset_demo удаляет результаты и черновики. Миграции после onboarding: общий
`20261111120000_service_drafts.sql` (один раз), затем
`20261111120300_self_check.sql`. RLS/revoke закрывают PUBLIC, существующие
anon/authenticated и sequences. Контракт HTTP/агента для Claude — в HANDOFF.
