# Регламент учебного код-ревью

Синтетический регламент учебного проекта, а не реальная политика компании.

## До отправки
Один pull request решает одну задачу. В описании укажи проблему, результат и способ
проверки. Прогони тесты, проверь форматирование и удали случайные отладочные записи.
При изменении поведения добавь пример до и после. Большую задачу обсуди с наставником
и раздели на самостоятельные части.

## Обсуждение
Автор просит ревью у наставника или согласованного участника команды. Комментарии
проверяют понятность, корректность и обработку ошибок. Если смысл замечания неясен,
задай уточняющий вопрос. Разногласия обсуждаются на примере кода и требований.

## Завершение
После исправлений повтори проверки и запроси повторное ревью. Учебный PR сливает
ответственный участник команды после одобрения; автор отмечает результат в задаче.

## Git и CI в учебной задаче
Отдельная ветка Git изолирует задачу; перед коммитом посмотри git diff.
CI автоматически запускает сборку и тесты после изменения кода. При красной
проверке прочитай лог и устрани причину перед слиянием.
