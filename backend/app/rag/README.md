# RAG: документы команды

`async retrieve(query, user, k=4)` возвращает фрагменты `{title, content, url}`.
Доступ — общие документы (`team IS NULL`) и точное совпадение с `user.team` для любой роли.
Фильтр стоит в SQL перед top-k; результат дополнительно проверяется в сервисе.
`k` ограничивает число фрагментов, поэтому у одного документа может быть несколько результатов.

## Загрузка демо

Из корня запущенного Docker-проекта:

```bash
docker compose exec backend python -m app.rag.ingest
```

Без Docker, из `backend/`, с `DATABASE_URL` в окружении или `backend/.env`:

```bash
uv sync --frozen
uv run python -m app.rag.ingest
uv run python -m app.rag.ingest --directory app/rag/demo_docs
```

Сначала должна быть применена миграция `supabase/migrations/20261110120000_rag_documents.sql`.
Docker применяет её автоматически только при создании нового volume базы. Для уже существующей
локальной базы можно применить файл без удаления данных:

```bash
docker compose exec -T db psql -v ON_ERROR_STOP=1 -U buddy -d ai_buddy < supabase/migrations/20261110120000_rag_documents.sql
```

К облачной базе миграцию применяет Claude после мержа. Загрузка выполняется от владельца
таблиц и заменяет документ с его фрагментами по `demo:<имя файла>` в одной транзакции.
Повторный запуск не создаёт дубликатов. Удаление файла с диска само по себе не удаляет его
из БД. Разбор метаданных всего каталога выполняется перед записью; транзакция — на документ,
поэтому после сбоя в середине каталога можно повторить загрузку.

## Формат markdown

Поддерживается простое front matter без YAML-кавычек, комментариев и многострочных значений:

```markdown
---
title: Название документа
team: Авито Доставка
url: https://example.invalid/demo
---
# Текст документа
```

`title` и `team` обязательны; только `team: null` делает документ общим. `url` необязателен,
`url: null` означает отсутствие ссылки. Неизвестные и повторные ключи вызывают ошибку.
Метаданные не попадают в текст фрагментов. В демо 10 файлов: 4 общих и по 3 на команду.
Они синтетические, без реальных данных или инструкций для ИИ.
Файлы читаются как UTF-8 с необязательным BOM, в том числе после сохранения в Блокноте Windows.
Перекрытие фрагментов начинается на границе слова; слова длиннее окна делятся по длине.

## Эмбеддер и хранилище

`Embedder.embed(texts)` — async, один конечный ненулевой вектор 1024 на текст.
`DeterministicEmbedder` — поддельный нормированный bag-of-words на SHA-256: не обращается
к сети и не моделирует смысл. Сейчас он используется и в демо, и в тестах.
Claude подключает GigaChat через `get_service()` в `__init__.py`. При смене модели необходимо
переиндексировать **все** документы тем же эмбеддером, которым векторизуется запрос.

`DocumentStore` закрывает запись и поиск. `PostgresDocumentStore` использует psycopg async
и `DATABASE_URL`; `InMemoryDocumentStore` нужен для офлайн-тестов. `get_service()` кэширует
один сервис на процесс. Изменение настроек требует перезапуска процесса.

`psycopg_pool.AsyncConnectionPool` создаётся лениво и открывается на общем event loop
при первом обращении к БД: 1–8 соединений, ожидание свободного соединения до 5 секунд.
Соединение возвращается в пул после коммита/отката; контекст команды и search_path заданы
только в транзакции. Async-код из CLI/Flask запускается через `app.async_runner.run()`.
При явном завершении работы пул можно закрыть через `run(store.close())` на том же цикле.

Без `DATABASE_URL` публичный retrieve возвращает `[]`, как прежняя заглушка. Сбой поиска,
включая ошибку эмбеддера или ещё не применённую миграцию, записывается в лог и даёт `[]`:
чат продолжает отвечать без документов. Ошибки загрузки документов по-прежнему прерывают CLI,
чтобы оператор заметил неисправность. Проверка пустого запроса/`k <= 0` сосредоточена в сервисе.

## RLS

Миграция включает RLS для SELECT на обеих таблицах без создания ролей. Для непривилегированного
читателя DBA отдельно выдаёт SELECT на обе таблицы и USAGE на схему расширения, если нужно.
Новое расширение vector создаётся в схеме `extensions`; уже установленное в `public` поддерживается.
Права на таблицы и identity-последовательности отзываются у PUBLIC и, если они существуют,
у `anon`/`authenticated`: общие документы и эмбеддинги не открываются через Supabase REST.
Хранилище задаёт `app.rag_team` через `set_config(..., true)` внутри транзакции. Без контекста
команды читатель получает только общие документы; политик записи для него нет.
Владелец таблиц и суперпользователь обходят RLS по правилам PostgreSQL (в Docker это `buddy`),
поэтому явный параметризованный WHERE в поиске обязателен независимо от роли подключения.
Прямое подключение к БД считается доверенным; пользователь приложения не получает SQL-доступ.

## Тесты

```bash
cd backend
LLM_PROVIDER=echo uv run pytest --cov=app --cov-report=term-missing
```

Обычные тесты не требуют сети, ключей, PostgreSQL или Docker. SQL-адаптер проверяется
через поддельный пул/соединение, правила доступа — через in-memory хранилище и всех DEMO_USERS.

Дополнительные интеграционные тесты запускаются явно на Linux с локальным Docker daemon
и уже скачанным образом `pgvector/pgvector:pg17`:

```bash
LLM_PROVIDER=echo uv run --frozen --offline pytest --rag-postgres --cov=app --cov-branch
```

Они сами создают и удаляют временный контейнер, проверяют миграцию с отсутствующими и
существующими API-ролями, default privileges, схемы расширения, пул и сброс RLS-контекста.
Образ не скачивается тестом, реальная база и DATABASE_URL окружения не используются.

CLI загрузки закрывает DocumentStore.close() в finally после успешной загрузки и после ошибок
метаданных, эмбеддера или PostgreSQL. Загрузка и закрытие выполняются одним вызовом app.async_runner.run,
на одном event loop; только затем процесс завершает работу. InMemoryDocumentStore.close — no-op.
Это убирает предупреждения pending AsyncConnectionPool.worker при старте Docker.
