## 1. Зачем
Чек-лист, одинаковый для всех, заставляет стажёра тратить время на то, что он уже умеет, а наставника — объяснять
одно и то же. Эксперт на чекпоинте 1 одобрил персонализацию, но с условием: **общие для всех задачи не
персонализировать**. Поэтому план — это общий каркас команды плюс 2–3 учебных пункта по слабым темам карты навыков.
Главная идея продукта: «план, который растёт вместе со стажёром, а решает человек».

## 2. Пользователи и роли
| Роль | Что видит | Что делает |
|---|---|---|
| Стажёр | свой план: метки «для всех» / «для тебя», у персонального — «Почему: в карте навыков Git — новичок» | закрывает свои пункты, жмёт «Это я уже знаю» (спека 202) |
| Наставник | планы своих стажёров (метка «персональный» + причина), сравнение двух планов, каталог команды | добавляет пункт из каталога, убирает незакрытый персональный пункт |
| Руководитель | планы стажёров своей команды | — |
| Куратор | тип пункта, но не причину (карта навыков ему недоступна) | — |
| HR BP | планы недоступны | — |

## 3. Сценарий (основной путь)
1. Аня (Платформа объявлений, Git — новичок, SQL — уверенно) входит: в плане общие пункты команды с меткой «для всех»
   и «Практикум: Git» / «Практикум: CI» с меткой «для тебя» и подписью «почему».
2. Общий пункт по сильной теме остаётся обязательным: метка «ты это умеешь — коротко» и сжатое объяснение (спека 102).
3. Пётр (наставник) видит на экране сравнение: Аня и Кирилл — общие пункты совпадают, персональные разные (у Ани Git,
   у Кирилла SQL). Это не рейтинг.
4. Пётр добавляет Ане «+ Практикум: SQL» из каталога → у Ани в плане пункт «для тебя» с причиной «добавил наставник»
   и уведомление (спека 303). Или убирает незакрытый персональный пункт кнопкой «Убрать из плана».
5. Уровень по теме вырос (спека 202) → незакрытый персональный пункт по теме снимается, закрытые остаются.

### Альтернативные пути и ошибки
- Наставник пытается убрать общий пункт → `403`, кнопки у общего пункта нет.
- Убрать закрытый персональный пункт → `409` (история сохраняется).
- Чужой стажёр, чужой каталог, несуществующий пункт → `404`, неотличимо друг от друга.
- Пункт каталога уже в плане → в списке «Добавить пункт» его нет; одновременное добавление создаёт один пункт.
- Сервер без новых полей (старая версия) → интерфейс считает все пункты общими.

## 4. Поведение агента
- **Промпт:** сводка плана в системном сообщении (день, следующий шаг, уровень по темам, наставник, руководитель).
  Агент не называет тему «слабостью» — только факт из карты.
- **Инструменты:**

| Инструмент | read/write | Право | Аргументы | Результат |
|---|---|---|---|---|
| `get_plan` | read | `plan:read` | `intern_id?` | пункты с `kind` (`common`/`personal`), `reason`, `skill_level` |
| `get_skill_profile` | read | `skills:read` | `intern_id?` | уровни по темам |

- **Что агент НЕ делает:** не придумывает персональные пункты (только каталог), не убирает общие пункты, не меняет
  уровень, не показывает чужой план (отказ без подробностей).

## 5. Данные
- `backend/app/mcp_server/seed/onboarding.json`: `personal_catalog` — «тема + команда → учебный пункт с документом»,
  4–5 тем на команду. Каталог работает без ключа ИИ, результат одинаков при каждом запуске.
- Демо-стажёры с противоположными картами: Аня ↔ Кирилл (Пётр), Иван ↔ Лиза (Мария).
- Всё синтетическое; пункты и документы помечены как демо-данные, не регламенты Авито.

## 6. Интерфейс
- План стажёра: метки «для всех» / «для тебя», «Почему: …», «ты это умеешь — коротко».
- Экран наставника: блок «Сравнить планы: Аня и Кирилл» открыт сразу и стоит над карточками (проверка 12.11) — два
  столбца, персональные пункты фиолетовыми карточками друг напротив друга, общие приглушены одной строкой
  («оба: не начат»), первые 4 + «Показать все общие».
- Над планом стажёра у наставника — «Добавить пункт в план: Аня» (только записи каталога, которых нет в плане);
  у незакрытого персонального пункта — «Убрать из плана».

## 7. Критерии приёмки
- **AC-1.** Дано Аня (Git — новичок). Когда она открывает план. Тогда есть персональный пункт по Git с причиной,
  общие пункты помечены «для всех».
- **AC-2.** Дано тема `уверенно`. Когда строится план. Тогда общий пункт по теме остаётся с меткой «умеешь — коротко».
- **AC-3.** Дано уровень по теме вырос. Когда план пересобирается. Тогда незакрытый персональный пункт снят, закрытые
  и общие не тронуты.
- **AC-4.** Дано наставник своего стажёра. Когда он добавляет пункт из каталога или убирает персональный. Тогда план
  меняется, стажёр получает одно уведомление о добавлении; общий и закрытый убрать нельзя (403/409).
- **AC-5.** Дано чужой наставник, стажёр или несуществующий id. Когда запрашивают каталог или правят план. Тогда 404
  без различия причин.
- **AC-6.** Дано наставник с двумя стажёрами. Когда он открывает сравнение. Тогда видны общие пункты обоих и разные
  персональные с причиной; без процентов и баллов.
- **AC-7.** Дано перезапуск хранилища (PostgreSQL). Тогда каталог, персональные пункты и правки наставника сохраняются.

## 8. Метрики
- События `personal_item_added` / `personal_item_removed` в журнале событий (кто, тема, без текста).
- Цель кейса — сократить время на то, что стажёр уже знает: смотрим долю персональных пунктов, закрытых до срока,
  и число «Это я уже знаю» → «Поднять уровень» (спека 202).
