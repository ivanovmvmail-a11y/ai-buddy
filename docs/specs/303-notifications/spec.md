## 1. Зачем
После 11.11 у бота появились новые поводы написать первым: изменился уровень, добавлен пункт, отгул ждёт решения,
бот предлагает поднять уровень. Если каждый повод показывать по-своему, человек путается. Решение Миши: уведомления —
обязательная часть интерфейса, все поводы приходят через **уже существующие** колокольчик и сообщения бота, в одном
стиле — короткий текст и одно главное действие.

## 2. Пользователи и роли
| Кому | Повод (`kind`) | Текст (пример) | Главная кнопка |
|---|---|---|---|
| Стажёр | `skill_changed` | «Наставник отметил: Git — знаком. План обновился» | Открыть |
| Стажёр | `personal_item_added` | «В план добавлен пункт для тебя: Практикум: SQL (добавил наставник)» | Открыть |
| Стажёр | `absence_pending` | «Заявка на отгул ждёт 2 дня — напомнить руководителю?» | Напомнить |
| Стажёр | `absence_decided` | «Отгул на 12.11 согласован» | Открыть |
| Стажёр | `absence_today` | «Сегодня ты отсутствуешь, сроки пунктов сдвинуты» | Открыть |
| Стажёр | `plan_item`, `access_request` (были в 301) | «Пункт недели 1 просрочен» | Сделать сейчас |
| Наставник | `skill_suggestion` | «Бот предлагает поднять уровень: Аня Смирнова, Git (отмечено «это я уже знаю»)» | Решить |
| Наставник | `absence_fact` | «Аня Смирнова отсутствует 12.11» (без причины) | Открыть |
| Руководитель | `absence_new` | «Новая заявка на отгул на 12.11» | Решить |

Каждый видит только свои уведомления; чужие — 404.

## 3. Сценарий (основной путь)
1. Событие в сервисе (смена уровня, предложение, решение по отгулу, новый день) создаёт уведомление через одну функцию
   `notify` — с `kind`, текстом, целью перехода и ссылкой на объект.
2. В колокольчике у получателя появляется счётчик; бот дублирует текст сообщением в чате (с пометкой 🔔).
3. Главная кнопка ведёт к объекту: план, пункт, блок предложений, заявки на отгул, карточка стажёра. После перехода
   уведомление закрывается.

### Альтернативные пути и ошибки
- Один повод — одно активное уведомление: повтор не создаёт второе, «Напомнить завтра» скрывает до следующего дня.
- Отклонённое предложение по уровню стажёру **не приходит** (спека 202).
- Понижение уровня — нейтральная формулировка, без упрёков; при нескольких сменах темы активен только последний факт.
- Старое напоминание без `kind` — тип выводится по ссылке, как раньше.

## 4. Поведение агента
- **Промпт:** не меняется; уведомления создаёт сервис, а не модель.
- **Инструменты:** нет новых; агент не создаёт уведомления сам.
- **Что агент НЕ делает:** не пишет упрёков («ты опять не…»), не раскрывает причину отгула наставнику.

## 5. Данные
`backend/app/mcp_server/notifications.py` (`notify`, `complete`), поле `Reminder.kind/action` и ссылки
(`plan_item_id`, `request_id`, `suggestion_id`, `absence_request_id`); миграция `notification_links`.

## 6. Интерфейс
`frontend/src/components/ReminderBell.tsx`, `frontend/src/lib/notifications.ts`: текст, **одна главная кнопка по типу**
(«Открыть» / «Решить» / «Напомнить» / «Открыть в чате»). Решение Миши 12.11 после проверки:
- **факты** («Наставник отметил…», «Отгул согласован», «В план добавлен пункт…») — только «Открыть»; после нажатия
  уведомление уходит из колокольчика, куда бы ни вела кнопка;
- **ждут действия** (предложение по уровню, заявка на отгул, просроченный пункт) — главная кнопка и рядом тихая
  текстовая ссылка «Напомнить завтра» (обещанное в 301 «напомнить позже»);
- кнопки «Готово» нет: такое уведомление уходит само, когда дело сделано (решение по заявке или предложению, пункт
  закрыт), — без неё нельзя «закрыть» напоминание, не сделав дела.

## 7. Критерии приёмки
- **AC-1.** Дано смена уровня по предложению. Тогда стажёр получает одно уведомление-факт, без уведомления о
  персональных пунктах при пересборке.
- **AC-2.** Дано предложение по уровню. Тогда уведомление получает только наставник; отказ стажёру не приходит.
- **AC-3.** Дано наставник добавил пункт из каталога. Тогда стажёр получает одно «В план добавлен пункт…».
- **AC-4.** Дано заявка на отгул. Тогда руководитель — «Новая заявка», стажёр — решение, наставник — только дата.
- **AC-5.** Дано «Напомнить завтра». Тогда уведомление вернётся на следующий день стажёра, к которому оно относится.
- **AC-6.** Дано уведомление-факт. Тогда в интерфейсе одна кнопка «Открыть», и после неё уведомление уходит. Дано
  уведомление, ждущее действия. Тогда одна главная кнопка и ссылка «Напомнить завтра»; кнопки «Готово» нет ни у кого.
- **AC-7.** Дано перезапуск PostgreSQL. Тогда уведомления и их ссылки сохраняются без дублей.

## 8. Метрики
Доля уведомлений, по которым нажато главное действие; число «Напомнить завтра» подряд по одному поводу.
