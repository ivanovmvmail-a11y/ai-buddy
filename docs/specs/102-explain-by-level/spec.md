## 1. Зачем
Пункт плана сам по себе — одна строка («Открыть пространство команды»). Стажёру нужно понять, зачем это, как
сделать и к кому идти. Аня в Git новичок — ей нужны шаги; Иван в Git уверенно — ему хватит пары строк. Один и тот
же ответ обоим — либо скучно, либо непонятно. Эксперт на вебинаре 10.11: просто отвечать по чек-листу — «не решение»,
поэтому к объяснению добавляется **задание на практике**.

## 2. Пользователи и роли
| Роль | Что получает |
|---|---|
| Стажёр | объяснение своего пункта с глубиной по своей карте навыков; подсказка в строке плана: «здесь помогу подробно» (новичок) / «ты это знаешь» (уверенно) |
| Наставник, руководитель, куратор | объяснение без подстройки — карта навыков относится к стажёру |
| HR BP | плана не видит (спека 101) |

## 3. Сценарий
1. Аня (день 2) нажимает «Объяснить» у пункта «Открыть пространство команды» (тема Git, уровень «новичок»).
2. Бот: что за пункт → «Разберём по шагам — эта тема у тебя только начинается, это нормально» → 3 шага →
   задание на практике → источник (документ команды) → 2 кнопки-вопроса («Как это сделать по шагам?», «К кому идти?»)
   → кнопка действия «Сделать за меня», если пункт закрывается заявкой.
3. Иван нажимает «Объяснить» у того же пункта своего плана (Git — «уверенно»): «Ты в этой теме уверенно, поэтому
   коротко» → ссылка на документ → задание на практике.

### Альтернативные пути
- У пункта нет темы или уровень не указан → объяснение без подстройки.
- Пункт уже ждёт одобрения или закрыт → кнопки действия нет.
- Наставник поменял уровень (спека 104) → следующее объяснение уже с новой глубиной.

## 4. Поведение агента
- **Без ключа (сценарный режим, спека 003):** текст собирается на стороне интерфейса из данных плана и карты
  (`explainScripted`), модель не вызывается. Помечен «сценарный режим».
- **С моделью:** кнопка отправляет в `/chat` вопрос «Объясни пункт плана …». В системный промпт попадает
  «Уровень по темам: git — новичок, sql — уверенно», правило промпта: новичку — по шагам с примером, уверенному —
  коротко; **не говорить стажёру о «слабостях»**, уровень — только подсказка для глубины. Ответ — по документам,
  доступным пользователю, со ссылкой на источник.
- Задание на практике — подсказка, не проверка: бот его не оценивает.

**Изменение 13.11 (проверка в Docker с ключом GigaChat).** С моделью кнопка давала пустые шаги («1.» без текста),
показывала служебный `id` пункта, 5–7 источников и не учитывала уровень. Поэтому:
- **Кнопка «Объяснить» в обоих режимах** вызывает `POST /plan/items/{id}/explained` — ответ строит сервер по документу
  пункта и уровню стажёра (`app/agent/explain.py`), с практикой и подсказками. Подпись «по документу пункта · глубина
  по карте навыков». Модель для этой кнопки не нужна: всё, что она добавляла, — ошибки.
- **Свободный вопрос в чате с моделью:** сервер определяет тему вопроса (Git, SQL, CI — `app/agent/levels.py`) и
  уровень стажёра по ней, добавляет модели указание по глубине (новичку — 3–6 шагов с примером, уверенному — 2–3
  предложения) и открывает ответ строкой «Git ты знаешь уверенно — коротко…». Вопрос о самом уровне, ответ «нет в
  документах», черновик действия и роли кроме стажёра — без этой строки.
- Под ответом модели — не больше двух документов, самых близких к тексту ответа (`cited_sources`).

## 5. Данные
Пункт плана: `topic`, `summary`, `practice`, `doc_source_id`, `resource_id` (seed, спека 101). Уровень — из карты
навыков (спека 104). Новых таблиц нет.

## 6. Интерфейс
Кнопка «Объяснить» в строке пункта; подсказка уровня серым рядом с названием — только у своего пункта стажёра.
Ответ — сообщение бота в чате с источником и кнопками.
