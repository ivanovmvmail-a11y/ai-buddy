## 1. Зачем
Карта навыков с найма устаревает уже через неделю: стажёр растёт, а план продолжает предлагать ему азы. Автоматическая
оценка человека ИИ — недопустима (продуктовое правило команды и ответ эксперта). Решение: бот замечает повод и
**предлагает** наставнику поднять уровень, а решает наставник одной кнопкой — 10 секунд вместо разговора на 1:1.

## 2. Пользователи и роли
| Роль | Что видит | Что делает |
|---|---|---|
| Стажёр | у пункта по своей теме `новичок`/`знаком` — кнопку «Это я уже знаю»; после решения — только результат | отмечает «Это я уже знаю» и может убрать отметку |
| Наставник этого стажёра | карточку в чате «Похоже, … уже знает тему. Поднять уровень?» с основанием (с 14.11; раньше — блок над планом) | «Поднять уровень» / «Оставить» |
| Остальные | предложения не видят; запрос чужого — 404 | — |

## 3. Сценарий (основной путь)
1. Аня у пункта «Практикум: Git» нажимает «Это я уже знаю». Пункт не закрывается, уровень не меняется; под пунктом —
   «Отмечено: это я уже знаю. Наставник решит, поднять ли уровень» и «Убрать отметку».
2. Создаётся предложение «Аня Смирнова, Git: новичок → знаком, основание: отмечено «это я уже знаю»». Наставник Пётр
   получает уведомление «Бот предлагает поднять уровень…» с кнопкой «Решить» (спека 303).
3. Пётр нажимает «Поднять уровень» → уровень меняется, план Ани пересобирается (спека 105): незакрытый
   «Практикум: Git» снимается. Аня получает «Наставник отметил: Git — знаком. План обновился».
4. Второй повод — дела: стажёр закрыл **2 пункта** по теме → предложение с основанием «закрыто 2 пункта по теме Git».

### Альтернативные пути и ошибки
- «Оставить» → уровень не меняется; стажёр **ничего не видит** (отказ не показывается). Новое предложение по теме —
  только при новом поводе.
- Тема уже `уверенно` → предложения нет; кнопки «Это я уже знаю» нет.
- Повторные отметки и одновременные поводы → одно открытое предложение, к нему добавляются основания.
- Наставник сменил уровень вручную → открытое предложение снимается (`dismissed`).
- Устаревшее предложение не понижает уровень.

## 4. Поведение агента
- **Промпт:** уровень ставит только наставник; бот использует его для глубины объяснения, а не для оценки.
- **Инструменты:** агент предложения не создаёт и не принимает — они идут через сервис «Найм» и экран наставника.
  `get_skill_profile` (read, `skills:read`) — чтение уровня своему стажёру/наставнику.
- **Что агент НЕ делает:** не меняет уровень, не говорит стажёру о «слабости», не сообщает об отклонённом предложении,
  не участвует в решениях о судьбе стажёра.

## 5. Данные
`backend/app/mcp_server/hiring.py`: `SkillSuggestion {id, intern_id, mentor_id, topic, from_level, to_level, basis,
evidence[], status: pending|accepted|dismissed}`, порог `SUGGESTION_THRESHOLD = 2` закрытых пункта. Уровни:
`новичок → знаком → уверенно`, за раз — на одну ступень.

## 6. Интерфейс
- План стажёра: кнопка «Это я уже знаю» у пунктов по темам `новичок`/`знаком`, после отметки — подпись и «Убрать отметку».
- Экран наставника: карточка решения в чате (с 14.11; в плане — счётчик «Ждут твоего решения: N»): «Аня Смирнова, Git: новичок → знаком»,
  «Основание: …», кнопки «Поднять уровень» / «Оставить», подпись «Решаешь ты. Стажёр увидит только результат».

## 7. Критерии приёмки
- **AC-1.** Дано пункт по теме `новичок`. Когда стажёр жмёт «Это я уже знаю». Тогда пункт не закрыт, уровень не
  изменён, у наставника этого стажёра — одно предложение.
- **AC-2.** Дано стажёр закрыл 2 пункта темы. Тогда создаётся одно предложение с основанием «закрыто 2 пункта…».
- **AC-3.** Дано предложение. Когда наставник «Поднять уровень». Тогда уровень на ступень выше, план пересобран,
  стажёр получает один результат.
- **AC-4.** Дано предложение. Когда наставник «Оставить». Тогда уровень прежний, стажёр уведомлений не получает.
- **AC-5.** Дано любая роль, кроме наставника стажёра, или несуществующий id. Тогда 404, неотличимо.
- **AC-6.** Дано тема `уверенно` или нет наставника. Тогда предложений нет (никакой автоматической оценки).
- **AC-7.** Дано перезапуск PostgreSQL. Тогда предложения и основания сохраняются.

## 8. Метрики
События `skill_suggestion_created`, решения наставника (принято/оставлено) — сколько раз план «вырос» без встречи.
