## 1. Зачем
Организаторы не передают нам ключ, а их ключ может не подойти (нет оплаченных эмбеддингов, сеть). Эксперт
должен пройти основной путь демо **без ключа** одной командой. Заглушка `echo` только повторяет сообщение —
этого мало: в чате не работают «что дальше», заявка, отказ и «нет в базе».

## 2. Пользователи и роли
Все роли; права те же, что с настоящей моделью: сценарный режим ходит через те же инструменты агента
(`ToolExecutor`), значит проверка прав и черновики работают одинаково. Режим не получает данных больше, чем модель.

## 3. Сценарий (основной путь, без ключа)
1. Аня входит → приветствие, план, следующий шаг (интерфейс, спека 101).
2. «Объяснить» у пункта → объяснение под уровень (интерфейс, сценарный ответ по плану и карте навыков).
3. В чате «Что мне делать дальше?» → режим вызывает `get_plan` и отвечает следующим шагом и тем, кого ждём.
4. «Оформи мне доступ в Jira» → `list_access_resources` → `create_access_request` → **черновик** (не выполнено).
5. «Покажи план Ивана» от Ани → `get_plan(intern-ivan)` → отказ без подробностей.
6. Вопрос по документам («Как отправить pull request?») → фрагмент найденного документа с источником.
7. Вопрос, которого нет в документах (или документ чужой команды) → «в базе этого нет», к кому идти и
   **черновик вопроса** наставнику, который стажёр копирует сам.
8. Организационный вопрос (отпуск, больничный, документы, компенсации) → сразу к HR BP.

### Альтернативные пути и ошибки
- Сервис не ответил / инструмент вернул ошибку → «Сервис временно недоступен, попробуй позже».
- Наставник: «Какие заявки ждут меня?» → `list_access_requests`.

## 4. Поведение агента
- Провайдер `LLM_PROVIDER=scenario` реализует тот же интерфейс, что GigaChat (`LLMProvider.chat`), и может
  просить вызвать инструменты. Намерение определяется по ключевым словам вопроса; ответ собирается из
  результата инструмента или из фрагментов документов, которые агент передал в контексте.
- Режим **не выдумывает**: каждое утверждение — из инструмента или из документа.
- Режим по умолчанию без ключа (`.env.example`, Docker). `echo` остаётся для разработки.
- Интерфейс показывает «сценарный режим (без ключа модели)» в демо-панели.

## 5. Данные
Те же: seed имитаций сервисов (спека 101) и демо-документы RAG. Отдельных «заготовленных ответов» нет.

## 6. Интерфейс
Без изменений, кроме: «Объяснить» в режиме `scenario` даёт сценарный ответ так же, как в `echo`.

## 7. Критерии приёмки
- **AC-1.** Дано режим `scenario`. Когда стажёр спрашивает «что дальше». Тогда ответ называет следующий шаг из `get_plan`, а если есть ожидание — кого ждём и сколько дней.
- **AC-2.** Когда стажёр просит доступ к Jira. Тогда создаётся черновик `create_access_request` с `level=read`, заявка в сервисе **не** создана, ответ не говорит «готово».
- **AC-3.** Когда стажёр просит план другого стажёра. Тогда отказ без данных чужого плана.
- **AC-4.** Когда в контексте есть документ со словами вопроса. Тогда ответ — фрагмент документа (источник показывает API).
- **AC-5.** Когда подходящего документа нет. Тогда «в базе этого нет», к кому идти и черновик вопроса.
- **AC-6.** Когда вопрос организационный. Тогда направление к HR BP.
- **AC-7.** Когда наставник спрашивает про заявки. Тогда список заявок, ждущих его.
- **AC-8.** Когда инструмент вернул ошибку. Тогда понятное сообщение без внутренних деталей.

## 8. Метрики
Те же события, что с моделью: режим проходит через агента. В отчёте золотого набора — отдельная колонка
«сценарный режим», чтобы видеть, что основной путь проходится без ключа.
