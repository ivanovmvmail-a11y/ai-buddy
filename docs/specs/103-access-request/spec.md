## 1. Зачем
Первая неделя стажёра — во многом ожидание доступов: трекер, база знаний, пространство команды. Стажёр не знает,
где подать заявку, что писать в обосновании и какой уровень прав просить, а потом — у кого она застряла. Это главное
**действие** сценария: ТЗ требует, чтобы ассистент не только отвечал, но и делал что-то через сервис. При этом
решает человек: бот готовит, стажёр подтверждает, владелец ресурса одобряет.

## 2. Пользователи и роли
| Роль | Что может |
|---|---|
| Стажёр | видеть ресурсы своей команды; получить черновик заявки и подтвердить или отменить его; видеть свои заявки |
| Наставник | видеть заявки своих стажёров; **одобрить** или **отклонить с причиной** заявку, где он согласующий |
| Руководитель, куратор, HR BP | заявки не подают и не решают |
| Бот | только готовит черновик; сам заявку не подаёт и не одобряет |

Ресурс чужой команды и несуществующий ресурс неотличимы: «не найдено».

## 3. Сценарий
1. Аня нажимает «Сделать за меня» у пункта «Открыть пространство Платформы объявлений» (или просит в чате).
2. Бот показывает карточку черновика: ресурс, уровень прав **«чтение»** (минимально достаточный), обоснование
   «Стажировка в команде …», кто согласует (наставник Пётр). Подпись: «без тебя ничего не отправлю».
3. Аня нажимает «Подтвердить» → сервис возвращает номер заявки `REQ-…` и статус «на согласовании»; пункт плана —
   «ждёт другого человека: Пётр».
4. Пётр входит → бот сразу говорит, что ждёт его одобрения; на экране — «Одобрить» / «Отклонить».
5. «Одобрить» → доступ выдан, пункт Ани «сделано», следующий шаг меняется.
   «Отклонить» → причина обязательна; пункт возвращается Ане в работу с этой причиной; можно подать заново.

### Базовые доступы
Трекер (Jira) и база знаний (Confluence) сервис выдаёт сразу после подтверждения (`approver = auto`) → пункт «сделано».

### Ошибки
- Повторная заявка на тот же ресурс, пока прежняя не отклонена → при подтверждении «Заявка на этот ресурс уже
  существует»; карточка черновика — «не выполнено» с этим текстом.
- Отмена черновика → ничего не создаётся.
- Одобрить чужую заявку или заявку не на согласовании → отказ (`403` / `409`); стажёр одобрить не может.
- Подтвердить чужой черновик → «не найдено»; права проверяются заново в момент подтверждения.

## 4. Поведение агента
- Инструменты: `list_access_resources`, `list_access_requests` (чтение), `create_access_request` (запись → черновик),
  `decide_access_request` (запись, только наставник → черновик для наставника).
- Промпт: пункт с доступом закрывается заявкой; предлагать уровень `read`; не писать «подал» или «готово», пока
  человек не нажал «Подтвердить».
- Сценарный режим без ключа (спека 003) ведёт тот же путь: «Сделать за меня» → черновик.

## 5. Данные
- `AccessResource {id, title, kind: base|team_space, team, approver: auto|mentor, fields}` — **согласующий — поле
  ресурса**, а не правило в коде: по ответу организаторов в Авито он зависит от типа ресурса (владелец проекта,
  руководитель, DevOps). `fields` — настраиваемый список полей заявки у ресурса.
- `AccessRequest {id, intern_id, resource_id, level: read|edit|admin, justification, status: pending_approval|granted|rejected, approver_id, reject_reason, plan_item_id, created_day}`.
- События: `access_request_created`, `access_request_decided` (одобрил или отклонил, причина). Хранение — PostgreSQL.
- Отдельного портала заявок нет (эксперт: «не нужно»): тонкая имитация сервиса и MCP-инструменты.

## 6. Интерфейс
Кнопка «Сделать за меня» у пункта с доступом и в приветствии; карточка черновика в чате с «Подтвердить» /
«Отменить»; у наставника — заявки на одобрение с «Одобрить» / «Отклонить» (поле причины).
