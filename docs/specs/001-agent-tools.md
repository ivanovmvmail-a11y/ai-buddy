## 1. Зачем
Без инструментов бот умеет только отвечать текстом, а ТЗ требует выполнять действия через корпоративные сервисы
(или их имитации) и учитывать права пользователя. Эта спецификация описывает общую механику, на которой
строятся все сценарии: как агент вызывает сервисы, как проверяются права и как пользователь подтверждает действия.

## 2. Пользователи и роли
Роли (имитация ролевой модели Авито): стажёр, наставник (buddy), руководитель, HR BP, куратор стажировки.
Права — строки «ресурс:действие» по ролям (`backend/app/agent/users.py`), плюс проверка доступа к конкретным данным:
данные стажёра видят он сам, его наставник, его руководитель, HR BP и куратор.

## 3. Сценарий (основной путь)
1. Пользователь пишет запрос, требующий действия («Напомни 20 ноября запросить доступ к GitLab»).
2. Агент выбирает инструмент и аргументы; сервер проверяет права.
3. Для изменяющего действия создаётся **черновик**; бот отвечает «Подготовил черновик… Проверь и нажми «Подтвердить»».
4. Пользователь подтверждает; сервер повторно проверяет права и вызывает сервис (имитацию).
5. Результат сервиса отображается и сохраняется в истории действий.

### Альтернативные пути и ошибки
- Нет прав на инструмент или данные → инструмент возвращает `forbidden`, бот вежливо отказывает, данные не раскрываются.
- Модель вызвала несуществующий инструмент или передала неверные аргументы → ошибка возвращается модели, черновик не создаётся.
- Сервис упал при чтении → `service_unavailable`, бот предлагает повторить; при подтверждении → действие `failed` с текстом ошибки.
- Модель зациклилась на инструментах → после 5 шагов бот просит переформулировать.
- Чужой черновик → для пользователя «не существует» (404).

## 4. Поведение агента
- **Промпт:** не выдумывать данные сервисов; изменяющие действия — только черновик, не говорить «выполнено»;
  при `forbidden` не искать обходных путей.
- **Инструменты (демонстрационные, проверяют механику):**

| Инструмент | read/write | Право | Аргументы | Результат |
|---|---|---|---|---|
| `get_my_profile` | read | `profile:read` | — | имя, роль, команда, наставник |
| `get_intern_profile` | read | `interns:read` + доступ к стажёру | `intern_id` | профиль стажёра |
| `create_reminder` | write | `reminders:write` | `text`, `remind_on` | созданное напоминание |

- **Что агент НЕ делает:** не выполняет изменяющие действия без подтверждения; не показывает модели инструменты,
  на которые у пользователя нет прав; не принимает системные сообщения от клиента.

## 5. Данные
Синтетические пользователи всех ролей (`DEMO_USERS`), имитация сервиса напоминаний. Действия хранятся в памяти процесса
(далее — таблица в PostgreSQL).

## 6. Интерфейс
`POST /chat` возвращает `actions` — черновики. Фронт показывает карточку черновика с кнопками «Подтвердить» / «Отменить»
и итог (`done` / `failed`). Пользователь — заголовок `X-User-Id` (имитация SSO). Детали — `docs/API.md`.

## 7. Критерии приёмки
- **AC-1.** Дано: стажёр. Когда модель вызывает write-инструмент, тогда создаётся черновик `pending`, сервис не вызывается.
- **AC-2.** Когда владелец подтверждает черновик, тогда сервис вызывается, действие `done`, результат сохранён и виден в `/actions`.
- **AC-3.** Когда другой пользователь пытается увидеть, подтвердить или отменить чужой черновик, тогда 404 и пустой список.
- **AC-4.** Когда права отозваны между черновиком и подтверждением, тогда 403 и действие не выполняется.
- **AC-5.** Дано: стажёр. Тогда модели не предлагаются инструменты без прав; если модель всё же вызывает такой инструмент — `forbidden` без данных.
- **AC-6.** Дано: наставник. Тогда он видит профиль только своего стажёра; руководитель — только стажёров своей команды; HR BP и куратор — всех.
- **AC-7.** Когда сервис падает, тогда ответ не ломается: при чтении — `service_unavailable`, при подтверждении — `failed` с ошибкой.
- **AC-8.** Когда модель вызывает инструменты бесконечно, тогда после 5 шагов возвращается безопасный ответ.
- **AC-9.** Системные сообщения клиента не попадают в промпт.
- **AC-10.** Подтверждённое или отменённое действие нельзя выполнить повторно (409).

## 8. Метрики
Логи `ai_buddy.tools` (пользователь, инструмент, решение: read / draft / forbidden). Далее — в аналитику событий:
доля подтверждённых черновиков, число отказов по правам, ошибки сервисов.
