# SDD-спецификации AI-buddy

ТЗ требует вести разработку AI-функций по SDD (spec-driven development) и приложить спецификации к сдаче.
Принцип: **сначала спецификация → потом код и тесты по ней**.

## Формат
С 10.11.2026 новые спецификации пишем в раскладке [spec-kit](https://github.com/github/spec-kit): папка на функцию
и три файла. Сам инструмент spec-kit не установлен — используем его структуру, шаблоны лежат в [`_template/`](_template/).

```
docs/specs/<NNN>-<slug>/
  spec.md    — что делаем и зачем: роли, сценарий, поведение агента, критерии приёмки
  plan.md    — как реализуем: модули, данные, контракты, проверка, что заменяется при внедрении
  tasks.md   — список задач: кто делает, какие критерии закрывает, в каком PR
```

Роль общих принципов проекта (в spec-kit это «constitution») выполняют [`AGENTS.md`](../../AGENTS.md)
и общая спецификация продукта [`docs/SPEC.md`](../SPEC.md).

Спецификации `001` и `002` написаны раньше одним файлом (тот же состав, что у `spec.md`) и оставлены как есть:
историю не переписываем, по ней видно, как менялся подход.

## Как работаем
1. Новая AI-функция (сценарий, инструмент агента, изменение промпта) начинается с `spec.md`. Статус `черновик`.
2. Спецификацию ревьюят люди (PR), статус → `принята`. После этого пишутся `plan.md` и `tasks.md`.
3. Код и тесты пишутся по задачам. Каждый критерий приёмки (`AC-…`) закрыт хотя бы одним автотестом —
   в таблице «Трассировка» указано, каким. Статус → `реализована`.
4. Меняется поведение — сначала правим спецификацию, потом код (в том же PR).

## Нумерация
- `0xx` — платформа агента (механика, безопасность, общие правила).
- `1xx` — сценарии стажёра.
- `2xx` — сценарии наставника, руководителя, HR BP, куратора.
- `3xx` — фоновые процессы (ИИ-крон, аналитика).
