# 006 — Feature flags: включить и выключить функцию без правки кода

Статус: **реализована (спецификация и код в одном PR, 14.11)** · Автор: Claude · Основание: ТЗ («в Авито есть feature
flags — compile-time и runtime», стек: Redis), полная проверка 14.11 («Redis и feature flags есть только на схеме»).

## 1. Зачем
Новые AI-функции (подбор ответа наставника по смыслу, проверка практикума по смыслу, выдача простого доступа в один
клик) в Авито выкатывались бы под флагом: включить на одной команде, быстро выключить при сбое — без релиза. В
прототипе это должно работать на деле, а не быть строкой в таблице «при внедрении».

## 2. Роли
Читать список флагов может любая вошедшая роль (в нём нет данных пользователей). Переключать — как демо-кнопки
«Сброс» и «Следующий день»: локально без пароля, на публичном сайте — с код-словом `DEMO_KEY`. В Авито — права
системы feature flags.

## 3. Поведение
Флаги (`backend/app/features.py`):

| Флаг | По умолчанию | Что делает | Если выключить |
|---|---|---|---|
| `quick_access` | вкл | «Сделать за меня»: доступ на чтение учебного сервиса — в один клик | всегда черновик → «Подтвердить» |
| `memory_recall` | вкл | «Память»: при ответе «в документах нет» модель сверяет вопрос с уже отвеченными вопросами команды (спека 108) | только поиск по словам |
| `practice_by_meaning` | вкл | Практикум: факт, не найденный по ключевым словам, модель проверяет по смыслу (спека 107) | проверка только по словам |
| `example_guard` | вкл | Из ответа модели убираются примеры, команды и «в Авито…», которых нет в документах | ответ модели без этой очистки |

Значение флага берётся по порядку: переключено на ходу → задано при запуске → по умолчанию.
- **При запуске** (аналог compile-time): `FEATURE_FLAGS="quick_access=off,memory_recall=on"`. Неизвестные имена и
  значения пропускаются.
- **На ходу** (runtime): `POST /features {"name", "enabled"}` — без перезапуска. Значение хранится в **Redis**
  (`REDIS_URL`; в Docker — служба `redis`), его видят все процессы backend. Без `REDIS_URL` — в памяти процесса.
- **Redis недоступен — не ошибка**: чтение и запись не роняют запрос, backend работает по значениям запуска;
  повторная попытка соединения — не чаще раза в 30 секунд, ожидание Redis — не больше 0,3 с.
- «Сброс» в демо-панели возвращает флаги к значениям запуска.
- Флаг — не право доступа: права по-прежнему проверяет сервер (спека 001). Выключенный флаг не открывает данных.

## 4. HTTP
- `GET /features` → `{"flags": [{"name", "enabled", "source": "default" | "env" | "runtime", "description"}], "store": "redis" | "memory"}`.
- `POST /features` `{"name": str, "enabled": bool}` → тот же список. Неизвестный флаг — `404`, не `bool` — `422`,
  без код-слова при заданном `DEMO_KEY` — `403`, без пользователя — `401`.

## 5. Критерии приёмки
| № | Критерий | Тест (`backend/tests/test_features_recall.py`) |
|---|---|---|
| AC-1 | Порядок значений: по умолчанию → `FEATURE_FLAGS` → на ходу; мусор в переменной пропускается; «Сброс» возвращает значения запуска | `test_flags_default_env_runtime`, `test_flags_http` |
| AC-2 | HTTP: список, переключение, 404 / 422 / 401, код-слово | `test_flags_http` |
| AC-3 | Значение на ходу пишется в Redis и читается из него; Redis упал — работа продолжается без ошибок | `test_flags_in_redis_and_redis_down` |
| AC-4 | `quick_access` выключен — простой доступ становится черновиком; включён — выдаётся сразу | `test_quick_access_flag_turns_one_click_into_draft` |
| AC-5 | `memory_recall` выключен — ответ наставника по перефразировке не подбирается | `test_recall_never_crosses_teams_and_respects_flag` |
| AC-6 | `practice_by_meaning` выключен — модель при проверке задания не вызывается | `test_practice_by_meaning_is_careful` |
| AC-7 | `example_guard` выключен — выдуманный пример из ответа модели не убирается | `test_example_guard_flag` |
| AC-8 | Адреса описаны в OpenAPI | `tests/test_integrations.py::test_openapi_describes_every_route` |
