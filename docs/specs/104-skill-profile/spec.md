## 1. Зачем
Стажёры приходят с разным уровнем: Аня уверенно знает SQL и путается в Git, Иван — наоборот. Одинаковые
объяснения одному скучны, другому непонятны. Карта навыков по темам говорит боту, насколько подробно
объяснять пункт плана. Стартовую карту заполняет наставник по итогам найма; дальше он её меняет сам.

## 2. Пользователи и роли
| Роль | Что может |
|---|---|
| Стажёр | видит свою карту (подсказка в плане: «здесь помогу подробно» / «ты это знаешь») |
| Наставник | видит карту своих стажёров и **меняет уровень по теме** |
| Руководитель, куратор, HR BP | карту не видят (SPEC 5: навыки — только стажёр и наставник) |

## 3. Сценарий
1. Пётр открывает карточку Ани: сильные стороны, темы для роста, «Уровень по темам» — Git: новичок, SQL: уверенно, CI: не указан.
2. После 1:1 Пётр ставит Git → «знаком».
3. Аня спрашивает про пункт по Git — бот объясняет короче, без азов.

### Ошибки
- Стажёр пытается поменять свой уровень → `403`. Чужой наставник или куратор → `404` (стажёра «не существует»).
- Неизвестный уровень → `422`.

## 4. Поведение агента
Агент читает карту (`get_skill_profile` и контекст промпта «Уровень по темам») и выбирает глубину.
**Менять уровень агент не может** — это не инструмент: ИИ человека не оценивает, решает наставник.

## 5. Данные
`SkillProfile {intern_id, skills: {тема: novice|familiar|confident}, strengths[], growth[]}`. Хранение — PostgreSQL
(спека 101-T3). Каждое изменение пишет событие `skill_level_changed` (кто, тема, было → стало). Баллов, рейтингов и
сравнения стажёров нет.

## 6. Интерфейс
В карточке стажёра у наставника — список тем (из карты и из тем пунктов плана) с выпадающим списком уровня.
Подпись: «Ставит только наставник. Бот подстраивает глубину объяснений, стажёра не оценивает.»
